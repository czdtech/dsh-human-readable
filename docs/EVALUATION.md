# 真实模型验收：6 个场景

`npm test` 只验证 prompt 规则、上下文打包、字面保护、失败保稿和写回契约；**不证明真实模型会照做**。这份表用于逐例记录真实模型的输出和耗时。

## 怎么跑

1. 重启 / 重载插件（改过 `host.js` 时）；刷新页面（改过 `client.js` 时）。
2. 在真实会话里构造对应上下文，输入草稿，按 `Alt+H`。
3. 打开 DevTools Console，过滤 `[human-readable]`，记录 `elapsedMs`、`changed`、`hasContext`。
4. 把结果填进下表。每个场景至少跑 2 次，看稳定性。

## 场景表

| # | 场景 | 上下文要点 | 草稿 | 期望 | 实际输出 | 耗时 | 结论 |
|---|---|---|---|---|---|---|---|
| 1 | 继续-截断 | 助手在一段代码/函数里写到一半被截断 | `继续` | 从断点继续，点名位置，不重复已输出内容 | | | |
| 2 | 继续-分步 | 助手列了三步计划，第一步刚完成 | `下一步` | 点名第二步的对象和任务 | | | |
| 3 | 可以-展示结果 | 助手已展示结果，没有问是否继续 | `可以了` | 只表示对结果的认可，不授权下一步 | | | |
| 4 | 可以-等待确认 | 助手明确问「要我现在改吗？」 | `可以` | 展开为「确认采用 X，开始做 Y」 | | | |
| 5 | 换色查不到 | 能定位到具体按钮/颜色，但上下文里没有目标色 | `这个颜色换一下` | 点名具体对象；目标色保持草稿原话，不猜颜色、不留占位 | | | |
| 6 | 原句已自包含 | 任意上下文 | 一句主谓宾完整、没有代词的话 | 基本原样返回，并提示「原文已经能独立看懂，未改动」 | | | |

另补两个边界：

- **字面保护**：草稿里带代码块、行内代码、链接、变量占位符，确认输出逐字保留；改坏或遗漏时应报错并保留原稿。
- **首条消息**：空白会话里按钮应是灰的，不能点。

## 通过标准

- 对象、步骤、文件名来自上下文，**不编造**；
- 不新增需求、背景、默认值或验收标准；
- 只有 #4 把「可以」展开成授权；#3 不越权；
- 只有 #5 对查不到的值保持草稿原话；任何场景都不出现 `[请填入]` 占位，也不留空；
- 只有 #6 允许原样返回；
- 代码块、链接、变量没有被改动或遗漏。

## 耗时观察

- 用 `[human-readable]` 里的 `elapsedMs` 记录端到端耗时，跑 10–20 次，算 P50 / P90。
- `elapsedMs` 包含模型元信息查询；`host.js` 的 8 秒计时**不含**元信息查询，两个数不是一回事。
- 如果 P90 明显超过 2 秒：先确认前缀缓存是否命中、模型是否太慢，不要直接放宽 8 秒；上下文是全量打包，属于刻意设计，不压缩。
- 如果出现 `max-tokens` 截断：考虑把 `MAX_OUTPUT_TOKENS` 从 800 提到 1000。
- 如果超时：再考虑 `DEADLINE_MS` 或换更快的模型。

## 失败分类

| 现象 | 先查什么 |
|---|---|
| #1/#2 原样返回 | 上下文是否真的包含断点/下一步；prompt 的空上下文测试是否被模型忽略 |
| 编了上下文里没有的名字 | 例子是否被当成模板；prompt 的「只在 context 里找依据」是否被稀释 |
| 输出变长、加了需求 | 是否把「自包含」误当成「扩写」；反例是否不够醒目 |
| #3 越权授权 | 授权护栏是否被跳过；助手最后一句是否真的在等确认 |
| #5 猜了颜色或留了占位 | 模型是否把「猜一个」当成了默认；「保持原话、不留占位」是否被忽略 |
| 超时 / 截断 | 模型是否太慢或输出太长；`reasoningEffort` 是否真的取到最低档 |
