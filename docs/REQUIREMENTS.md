# 需求梳理：给任何人讲清楚（Human-Readable）

> 项目代号：DSH-Human-Readable
> 形态：DeepSeek Harness 桌面版插件（Host + Web Client 双半）
> 状态：下方「当前实施规则」为现行约定，其后 §0–§11 保留早期需求与决策记录，不作为当前规格。早期「十人测试法」、强制四要素、两倍长度、独立快模型、取消按钮等已被后续规则取代；未标日期的实测属于早期版本。

## 当前实施规则（2026-11-07）

定位是「意图解压器」：把用户已经表达、藏在前情中的意思展开为一条脱离对话也能独立看懂、可以直接发送的消息。只补理解缺口，不替用户决定执行细节。

### 行为与边界

- 明确对象、动作和授权范围，保留第一人称、语气、精确引用与已有约束。查看不变执行，小改不变重做，认可不自动授权下一步。质量以空上下文测试验收：把改写后的句子单独拿给没看过对话的人，他能说出改哪个具体对象、做什么、范围到哪；只有原句已经独立通过才允许基本不变，原样返回时用轻提示说明未改动，不静默。
- 当前草稿是唯一改写对象。用户原话是决定与要求的证据，助手文字仅帮助定位讨论内容；未确认的助手建议不能转成用户需求。
- 上下文能回答的（指代、省略、对象、方案选择）一律补齐；上下文里真查不到的值（色号、路径、数量、名称）保持草稿原话，不猜、不插占位符、不留空给用户补。缺执行细节不等于缺意图；不新增默认选择或假设方案。
- 只做四类有上下文依据的小修改：还原指代、补全名称、删掉只在对话里成立的连接词、从上下文搬限定短语。不补上下文里没有的背景、需求、默认值或验收标准。
- 推进词按三种情况展开：输出中断时从断点继续；分步执行时点名下一步；只有上一轮明确在等确认时，才把「可以/好」展开为授权。只是展示结果时只表示认可。
- 不回答或执行草稿，不写助手式评价，不把文件路径、图片或附件引用当成已读取的内容。
- 不加模式、预览、撤销条、成功气泡（原样返回时的「未改动」轻提示除外）、独立模型设置、图片识别、代码库检索或外部服务。仍由用户发送；保留现有按钮、快捷键、失败提示与防覆稿。会话尚无已发送的用户消息时，按钮保持禁用并说明原因，避免零上下文空点。设置页只保留快捷键设置和模型跟随说明，不再提供轮数或 token 数值输入；读取旧本地设置时清除已退役字段并保留快捷键。

### 取数与生成

- 使用当前 Session 的 `deriveMessages()`，按 `source.kind === 'user'` 的真实用户输入分轮。助手出现前的连续用户输入合并；每轮保留用户原话和最后一条有文字的助手消息，不冒称是最终回复或用户刚看过的内容。
- 自动时间注入、其他非用户来源消息及工具结果不作为真实用户要求。助手多步消息不占多轮，不新增事件重放或投影服务。
- Host 内部不设轮数上限、不设 token 预算：会话全量真实用户轮与每轮最后一条助手文本原样打包，不截断；客户端请求只传 `sessionId` 与 `draft`，不再接受、回传或持久化用户轮数/token 数值。
- 明确分开 JSON 中的 `context` 与 `draft`，不另造关键词式「已确认要求」抽取器。
- system prompt 采用 Qoder 原版骨架、仅三处必要改写：角色边界（改写而非回复）、数据隔离（上下文用固定 ⟨CTX⟩ 标记、草稿用随机后缀 ⟨DRAFT_xxx⟩ 标记，信封按前缀缓存友好排序）、上下文能回答的都补齐、查不到保持原话、不留占位；不带示例。
- 跟随会话最新模型选择；保留原有模型日志查找并撤掉 400 事件窗口，避免长会话悄悄退回部署默认。没有会话选择才使用部署默认；仍取模型声明的最低推理档，不宣称一定关闭思考。
- 正常只调用一次 `llm.stream`，不做生成后评审、格式修复或二次改写；输出上限 800 tokens。生成阶段 8 秒后发出中止信号，模型元信息查询不在计时内，模型服务需响应中止信号。
- 超时、中止、截断、异常、空输出或缺少结束标记均失败，不写回半成品。草稿里的围栏代码、行内代码、HTTP(S) 链接和 `${变量}` / `{{变量}}` 占位符做局部字面及次数校验；改变或遗漏直接保留原稿，不额外调用模型修复。该校验不等于自动证明意图保真。

### 验收与证据界限

质量看空上下文测试与意义保持，不看长度、专业感或变动率。真实模型至少逐例检查 6 个场景：继续-截断、继续-分步、可以-展示结果、可以-等待确认、换色查不到保持原话、原句已自包含；另检查只查看不修改、关键对象不明不编造、精确技术片段保留。

Node 内置测试检查上下文来源和轮次、全量不截断、忽略外部数值调额、缓存友好信封顺序、旧设置清理、模型切换与长会话、一次生成、失败保稿、字面保护、prompt 契约（Qoder 原句保留、产品接线、无占位、无三栏简报残留、语言跟随）、等待时变稿不覆盖及卸载后不写回。模拟测试不证明模型语义质量或真实 React/编辑器表现；这两项须在加载新版后现场验收。宿主重载或重启另行安排，不由实现过程自动打断当前会话。

## 1. 原始表述 → 需求提炼

| 你的原话 | 提炼成需求 |
|---|---|
| 「我发了个『继续』，我知道什么意思，但说给别人别人是不懂的」 | 判据不是「专业」，而是「**脱离上下文也能听懂**」：把只有你懂的隐含前情，写进话里 |
| 「十个人，老的小的中年的，男的女的，讲给他们都能懂」 | **唯一质量指标：十人测试法**。任一人听完要追问「什么意思」，就算没做到 |
| 「一个提示词你给别人都讲不清楚，发给 ai，ai 肯定也不理解」 | 先让人看懂，AI 自然懂；不为模型做优化，为「人」做优化 |
| 「根据上下文信息释义」 | 必须读当前会话历史，把「这个 / 那个 / 上面那段」补全成具体对象 |
| 「一键」 | 输入框里的按钮，单击触发，不跳页、不弹窗、不二次确认 |
| 「不做一键还原」 | 替换即生效；不满意就自己清空重写、再点一次 |

⚠️ 一个形态上的澄清：你贴的那段分析里，竞品（AIPRM、prompt-optimizer、Chrome 插件）都是浏览器插件；**我们做的是 DSH 桌面版插件**——能直接拿到会话上下文、输入框和模型，这是浏览器插件给不了的。

- 市面主流是 **Prompt Optimizer**（模板库 / 学院派 / 越改越长）；

|---|---|
| 中文名 | 给任何人讲清楚 |
| 英文名 | Human-Readable |
| 一句话价值 | 让「只有你懂」变成「谁都懂」 |

## 3. 核心场景（以「继续」为标准案例）

> 上下文：上一轮 AI 给了 3 个方案，用户已选定方案 B，AI 刚写了个开头。
> 用户输入：**继续**
> 改写后：**接着上一轮选定的方案 B，把没写完的部分补完：先列 3 条执行步骤，每条一句话；再说明需要我提供哪些信息。不要重复已经写过的内容。**

| 场景 | 用户输入 | 改写目标 |
|---|---|---|
| 半句 / 省略 | 「继续」「这个改改」 | 把上文的对象、进度、格式补全进这句话 |
| 行话 / 黑话 | 「把链路串一下，出个可落地的」 | 换成任何人都懂的日常词，动作和产出说具体 |
| 情绪化 / 跳跃 | 「不对，我要的不是这个，要更……你懂吧」 | 把「更」拆成可判断的维度（长度？语气？受众？） |
| 长文堆积 | 一大段没分段的需求 | 信息一条不丢，重排成「要什么 / 有什么限制 / 给我什么」 |

### 明确不做

- ❌ 一键还原 / 撤销条（你已明确不要；不满意自己清空重写）
- ❌ 改写风格设置（只有一个指标：谁都听得懂，没有第二档）
- ❌ 单独的界面语言设置 / 中英双语开关（跟随宿主）
- ❌ 原 P1 全部不做：选中文本改写、已发送消息重写、多候选、token 对比、快捷键
- ❌ 不做提示词模板市场 / 模板库（AIPRM 路线）
- ❌ 不支持单独指定第三方模型（模型只跟随当前会话，见 D10）
- ❌ 自动发送（只替换输入框，发送键由用户点）
- ❌ 替用户新增需求、改变原意、编造上下文里没有的事实
- ❌ Chrome 扩展 / 独立网页版

## 6. 质量：唯一的指标

### 6.1 十人测试法

把改写后的这句话念给十个人听：**小孩、老人、中年人，男女都有，都不懂你的项目**。
只要**有一个人**听完还得问「什么意思」，这条改写就不合格。

判断的不是「用词是否高级」，而是「**没有任何隐含前提**」：

- 对象是谁、要做什么、做到什么程度、以什么形式交付——四件事都在字面上，不靠猜。
- 不用行话、缩写、内部代号；必须用时，第一次出现就解释。
- 「继续」「改改」「那个」这类词，必须换成具体内容。

### 6.2 改写规则（作为 System Prompt 的需求规格）

1. **语义守恒**：只做「显式化」，不新增需求、不改变意图、不加原文没有的约束。
2. **消解指代**：所有「这个 / 那个 / 上面那段 / 刚才的」替换成具体对象。
3. **补全四要素**：做什么、对什么做、有什么限制、要什么形式的产出。
4. **说人话**：短句、主动语态、日常词；不用 `[ROLE]` / `[CONSTRAINT]` 这类标签。
5. **长度纪律**：默认不超过原文的 2 倍；宁短勿长。
6. **不硬编**：上下文不足以确定时，把不确定点写成明确的问句，而不是猜一个填上。
7. **只输出正文**：不要前言、不要「以下是改写结果」、不要说明。

### 6.3 时间预算（< 2 秒）

| 项 | 预算 |
|---|---|
| 端到端 | P50 ≤ 1.2s，上限 **2s** |
| 上下文 | 最近 **N 轮**（默认 6，可配 0–20）；总量 ≤ 3000 tokens，超出按 token 截断、保留最近的 |
| 输出 | ≤ 400 tokens |
| 模型 | 复用当前会话模型；**本次调用强制关闭思考链**：传最低推理强度；该模型关不掉思考时改用设置里的快模型 |
| 重试 | 不自动重试（重试由用户再点一次） |
| 超时 | 2s 未完成继续转圈但不禁用；8s 硬中止并提示 |

> **实测（20 次连续，deepseek-flash）**：P50 **1018ms**，最快 691ms，最慢 **1906ms**；20/20 进 2 秒，18/20 进 1.5 秒。最慢那次只输出 86 字，说明是首 token 排队，不是回答太长。

> 关于「关思考」：`reasoningEffort` 能单次压低推理强度，但有些模型（reasoner 类）天生就是推理模型，参数只能降档、关不掉。这种情况本次调用改用设置里指定的快模型；没指定就按最低档跑，超过 2 秒记为不合格，并在设置页说明原因。

> 代价说明：为了 2 秒，上下文默认只取最近 6 轮。指代超过 6 轮的情况会补不全——这是刻意接受的取舍，所以轮数做成了可配置项。

### 6.4 换成其他平台的模型，效果一样吗？

**功能一样，效果不完全一样。** 上下文是我们打包好发给模型的，任何模型收到的输入都相同——所以差异只在模型自身，集中在三处：

| 差异 | 具体表现 | 影响 |
|---|---|---|
| **速度** | 小尺寸 / 非思考模型（flash、mini、turbo 档）能守住 2 秒；大模型和思考模型必然超时 | 决定能不能用 |
| **指令遵循** | 「只输出正文」「不加原文没有的约束」「不超长」这几条，小模型容易破功，会自己加「以下是改写结果」 | 输出要后处理或重试 |
| **中文口语** | 「链路串一下」「出个可落地的」这类黑话，国产模型手感更好；部分海外模型会逐字直译 | 十人测试法达标率下降 |

结论与建议：

- **默认跟随当前会话最稳**：同一个模型，对上下文的理解最一致，不用额外调。
- 单独指定时，优先选**同尺寸或更小的非思考模型**；为 2 秒考虑，flash / mini / turbo 档更合适。
- 插件**不自己存 API Key**，只用你已经在 DSH 里接入的模型提供方：先在 DSH 的模型设置里加好，插件设置里就能选到。
- 换个平台**不会**「更懂你的会话」——会话是我们喂给它的，不存在模型自己知道更多。

**进入实现前要验证的四件事**
1. 各模型 `reasoning.efforts` 里是否有「关闭 / 最低」档，以及最低档下单次改写能否稳定在 2s 内（量 20 次）。
2. 写回输入框时，附件 / @引用 / 草稿结构是否会被破坏。
3. 无模型、未登录时的失败形态，确保原文不动。
4. 插件设置页里如何列出可选模型（provider / model 目录的读取方式）。

---

## 8. 非功能需求

- **隐私**：只把文本发给用户自己配置的模型；不落盘改写历史；日志不记原文。
- **可卸载**：卸载后输入框与历史完全恢复，不残留 DOM / 存储。
- **稳定**：Host 侧任何异常都不能让插件 UI 崩溃。
- **不打断**：生成期间输入框不锁、不抢焦点、不改变滚动位置。

## 9. 风险

| 风险 | 影响 | 对策 |
|---|---|---|
| 误点丢原稿（无确认 + 无撤销） | 用户白写一段 | **你已接受**；写回前在内存留一份快照，仅供本次会话重试时复用，不提供 UI 入口 |
| 2 秒目标在慢模型上达不到 | 核心体验崩塌 | 关思考 + 压上下文 + 压输出；实测不达标就换更快的模型跑这一路 |
| 改写后反而更长更难读 | 核心价值被破坏 | 长度上限 + 十人测试法抽检 |
| 模型把猜测写成事实 | 用户被误导 | 规则 6：不确定就写问句 |
| 上下文外发敏感内容 | 隐私事故 | 只带 6 轮、只带文本、明示发送范围 |
| 输入框状态冲突（附件、引用） | 数据丢失 | 覆盖前快照，检测到结构变化则改插入 |
