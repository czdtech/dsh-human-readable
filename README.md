# 给任何人讲清楚 · Human-Readable

一个 DeepSeek Harness 桌面版插件：**把输入框里只有你自己懂的草稿，结合当前对话上下文，澄清成一条脱离这段对话也能独立看懂、可以直接发送的版本。**

它解决的不是「提示词不够专业」，而是「你没把自己脑子里的隐含信息写出来」。

> 判断标准：把改写后的句子单独拿给一个没看过这段对话的人，他能说出要改哪个具体对象、做什么动作、范围到哪。补「理解缺口」，不替用户决定「执行细节」；不以字数、专业感或变动率衡量质量。

---

## 它长什么样

输入框右下角、发送键左边有一枚星光按钮：

1. 写下你想说的话，哪怕只有「继续」「可以了」这种半句；
2. 点一下按钮（或按快捷键）；
3. 输入框里的内容**直接变成**改写后的版本，你可以在原地改、或直接发送。

上下文里能查到的信息（哪个对象、哪个方案、「2」指什么）都会被补齐；上下文里真查不到的，保持你草稿里的原话——不编造、不插占位符、不给你留填空。

如果这是会话里的第一条消息（还没有任何已发送的消息），按钮是灰的：此时没有上下文可参考，改写不会产生有效变化。发送第一条消息后按钮就会亮起。

没有确认弹窗、没有撤销条——不满意就清空重写。

改写结果没有真正写进输入框时会明确报错，不会静默失败；原样返回时会说明「未改动」。

## 安装

需要 DeepSeek Harness 桌面版（本机 profile），并具备插件管理能力。

```text
plugin_manager  action=install_bundle  target=<本仓库的绝对路径>
```

插件是纯 JavaScript，无构建步骤、无依赖安装、无外部 API Key：

- Host 半：`host.js`，注册一条本机 HTTP 路由，读会话上下文并调用当前会话的模型；
- Client 半：`client.js`，往输入框工具行注入按钮，并把结果写回草稿。

## 设置

设置 → 给任何人讲清楚：

| 项 | 行为 | 默认 |
|---|---|---|
| 快捷键 | 任意含 Ctrl / Alt / Cmd 的组合，也可清除 | `Alt+H` |
| 模型 | 固定跟随当前会话，不单独设置 | — |

不再提供上下文轮数和 token 上限的用户数值设置。宿主内部不做任何截断：会话全量真实用户轮 + 每轮最后一条助手文本原样打包，不设轮数上限、不设 token 预算。升级后，本地保存的旧轮次/token 字段会被清理，原有快捷键保留。

只读取当前会话可见的消息，以真实用户输入分轮；助手回复前的连续用户输入合为一轮，每轮保留用户原话和最后一条有文字的助手消息。自动时间注入、工具消息不作为用户要求，助手的多条中间文字不占多轮，也不被冒称为最终回复。

全量上下文按旧到新排列打包，不做截断。信封把稳定的上下文放在前面、草稿放在后面，重复点击时前缀可命中模型服务的前缀缓存；草稿用每次请求随机后缀的标记包裹，防止草稿里的文字伪造分隔符。

界面文案跟随 Harness 的语言设置，没有独立的语言开关。

## 已知限制

- **首条消息不能改写**：按钮要求会话里至少有一条已发送的消息，否则保持禁用并在悬停时说明原因。零上下文时按钮保持禁用，不会空点。
- **只跟随当前会话的模型**：不支持单独指定第三方模型。实测把慢模型（如带思考链的 gemini）接进来单次要 9 秒以上，与「一键、2 秒内出结果」的产品前提冲突，因此不做。
- **生成阶段 8 秒超时**：发出中止信号；超时、中止、输出截断、异常或未收到结束标记，哪怕已收到部分文字也一律失败，不写回半成品。模型服务须响应中止信号；模型元信息查询不计入这 8 秒。
- **要快**：早期 deepseek-flash 实测 20 次，中位 1018ms、最慢 1906ms，全部进 2 秒；这不是新版提示词的性能实测或所有模型的保证。
- **只补齐，不替你决定**：保持对象、动作强度、约束和授权范围；上下文能回答的都补齐，查不到的保持你的原话；不新增默认选择或假设方案，不编造，不留空。
- **正常一次生成**：不做生成后评审、格式修复或二次改写。只有原句已经能脱离上下文独立看懂时才允许基本不变；原样返回时用一条轻提示说明「未改动」，不静默。
- **字面保护**：草稿里的代码块、行内代码、HTTP(S) 链接和 `${变量}` / `{{变量}}` 占位符若被改变或遗漏，直接失败并保留原稿，不再请求模型修复。这是局部字面校验，不是意图正确性的自动判定。
- 上下文取会话全量文本轮，不含工具消息；不读取图片、附件或路径指向的文件，不引入代码库检索。
- **等待期间继续输入**：草稿变化后通过宿主接口在原光标处插入改写结果，不覆盖新输入；宿主拒绝插入时保留现稿并提示，仍需检查插入后的整体意思。
- 仅支持 Harness 桌面版（Web GUI），不做 Chrome 扩展。

## 设计取舍

- **忠实优先**：必要术语、精确参数和「先看看」这类范围限定必须保留，不为通俗或完整而扩写。
- **自包含优先，但只搬上下文**：改写要能让没看过前文的人读懂；只搬上下文里已有的名称、步骤和限定语，不补背景、需求或默认值。助手建议不等于用户决定；缺对象或授权时才追问，不把所有细节补全当作目标。
- **失败不丢稿**：任何错误都不会动你输入框里的原文。
- **看得见结果**：写回没有生效会明确报错，原样返回也会说明「未改动」，避免「点了没反应」的错觉。
- **界面服从宿主**：按钮是 ghost 控件，错误用小气泡，不另造一套视觉语言。

## 测试

使用支持 `node:test` 和 MockTimers 的 Node.js（开发验证使用 Node 24 / 26），无需安装依赖：

```sh
npm test
```

测试用模拟宿主与模型检查数据打包、单次调用、prompt 规则、字面保护、失败不丢稿和写回契约，不证明真实模型的改写质量，也不替代宿主加载后的 UI 验收。改写效果需用真实的「上下文 → 草稿 → 结果」逐例检查，至少覆盖：继续-截断、继续-分步、可以-展示结果、可以-等待确认、换色查不到保持原话、原句已自包含。
